# Demo queries (SciFact, spring RRF of BM25 + MiniLM vs BGE-M3 All)

Run: `python pairs/11-bge-m3/demo.py --build` once (about 2 min on a Mac, 3.1 GB in `runs/demo_index/`), then `python pairs/11-bge-m3/demo.py --web` and open http://127.0.0.1:8765. Start it before the talk: loading the models takes about 20 s, then each query takes about 0.1 s.

The page shows the claim as each system reads it (BM25's words, with the ones no abstract contains crossed out; BGE-M3's sub-word pieces, shaded by sparse weight), then each system's top 10 with the labelled abstract highlighted. The tabs above each list are the methods, and the number under each tab is where that method ranks the labelled abstract; clicking a tab re-sorts the list in place. Keys: 1–4 run the examples below, A D S M H switch BGE-M3 between All three, Dense, Sparse, Multi-vector and Dense + sparse, / jumps to the search box. `python pairs/11-bge-m3/demo.py` without `--web` gives a plain terminal version.

- **Hero**: `#1221`, "The genomic aberrations found in matasteses are very similar to those found in the primary tumor." The labelled abstract, *Evolution of metastasis revealed by mutational landscapes…*, is at rank 29 for the spring pipeline and rank 1 for BGE-M3. The query misspells "metastases", the one word that names the topic, so BM25 can only match generic words (genomic, aberrations, tumor), while BGE-M3's sub-word tokens (`▁mata`, `stes`) still land near the right meaning: dense and multi-vector both put it first. Then `#1221 fr`, the same claim in French: the spring pipeline loses it (beyond rank 100), BGE-M3 keeps it at rank 1.
- **Failure**: `#659`, "Ivermectin is used to treat lymphatic filariasis." The spring pipeline ranks the labelled abstract first, BGE-M3 not at all. The abstract never says "ivermectin": it is about integrated control of tropical diseases, and BM25 finds it on "lymphatic filariasis". BGE-M3's sparse head alone would also rank it first, but in mode All the three heads only re-score the dense top 200, and dense puts it at 262. So the lexical head never sees it: the failure is in the candidate pool, not in the sparse head. On the page: the tabs read Dense 262, Sparse 1, Dense + sparse 53. Press S and the abstract slides up to rank 1. Press H (the paper's Dense+Sparse, which pools the top 1000 of both) and it comes back, but only to rank 53: with weight 0.3 on sparse, dense still dominates. So a bigger pool is not enough, the weights matter too. Same pattern for `#94` (albendazole): dense 78, sparse 1, final 28.
- **Wildcard**: taken from the room. Backup: "Le café réduit le risque de diabète de type 2." The spring pipeline drifts to unrelated abstracts (type 1 pregnancy outcomes, a protease inhibitor), BGE-M3 stays on type 2 diabetes prevention. No test label, so judge the lists by eye.

The demo re-implements mode All with numpy on the precomputed vectors (dense top 200 by exact inner product, same as the Faiss flat index); its ranks for `#1221` and `#659` match `analysis/scifact_vs_rrf.md`.
